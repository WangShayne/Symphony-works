# Symphony V1 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use agent-team-driven-development to execute this plan.

**Goal:** Build the confirmed Symphony V1 self-hosted development orchestration product by evolving the pinned upstream Elixir implementation into a durable, model-routed, multi-unit system with a governed Dashboard and isolated Docker Runner.

**Architecture:** Preserve upstream Codex, Linear, workspace, and Phoenix behavior behind new deep modules for Configuration, Coordination, Routing, Execution, Delivery, Security, and Operations. SQLite/Ecto holds authoritative state; external provider and Runner seams use production adapters plus deterministic test adapters. The Phoenix control plane never owns Docker access and all model, tool, tracker, and source-control effects are policy-checked and journaled.

**Tech Stack:** Elixir 1.19 / OTP 28, Phoenix 1.8, LiveView 1.1, Ecto 3.13, SQLite via `ecto_sqlite3`, Codex App Server, Docker Engine, Req, Jason, Gettext, Assent/OIDC, Erlang `:crypto`, OpenTelemetry, ExUnit, and Docker Compose.

**Authoritative requirements:** [`docs/design/v1-design-baseline.md`](../design/v1-design-baseline.md), [`CONTEXT.md`](../../CONTEXT.md), and [`docs/adr`](../adr/).

**Bootstrap constraint:** The current root is documentation-only and is not a Git repository. Task 1 runs in the current root, imports the upstream tree pinned at `7af5a7648c9fbffa08825fe0c0b18be00100aff3`, initializes Git, and commits the baseline.
